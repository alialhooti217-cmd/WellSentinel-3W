# CLAUDE.md: WellSentinel-3W

## Goal
Early-warning system for undesirable events in offshore oil wells (Petrobras 3W dataset v2.0.0, CC BY 4.0).
Portfolio project by Ali Al Hooti (chemical & process engineer). Target: a finished, honest, public v1.0 whose
numbers are consistent everywhere and come from one source (`reports/final_results.json`).

## Folder map

## Pipeline order
| Step | Script | Output |
|---|---|---|
| 00 | `00_download_data.py` | `data/raw/3W` (~1.9 GB, resumable) |
| 01 | `01_build_inventory.py` | `data/interim/inventory.csv` with well-grouped folds |
| 02 | `02_build_features.py` | `features.parquet` (or `features_physics.parquet` when `features.physics: true`) |
| 03 | `03_train_baseline.py` | single model (`--all-real` = deployable model, `--drop-sensors`, `--tag`) |
| 04 | `04_leakage_check.py` | SUPERSEDED by 06 (history only) |
| 05 | `05_social_figures.py` | marketing figures + facts sheet (needs 06) |
| 06 | `06_cross_validation.py` | 5-fold grouped (+ random) CV: `reports/cv_results*.json`, `cv_summary*.csv` |
| 07 | `07_sensor_reliance.py` | sensor permutation importance + ablations |
| 08 | `08_compare_cv.py` | per-class / per-fold comparison of CV runs |
| 09 | `09_results_table.py` | `reports/final_results.{json,md}`, the single source of truth for numbers |

Long runs: every training script takes `--folds` and `--max-iter` and prints progress. One HGB fit takes ~1–2 min.

## Ground rules
- Work on a branch (never commit straight to `main`); commit after each phase with a clear message.
- Never commit `data/`, `models/*.joblib`, `models/cv/` or large parquet files (see `.gitignore`).
- A well never appears in both train and test. Simulated + hand-drawn instances are training-only.
- Report metrics only as **5-fold grouped-CV mean ± std**. Headline = **strict** event metrics
  (alarm OFF at onset, then raised; pre-onset alarms are false alarms, not detections).
  Single-fold numbers (E00) are history, not results.
- **Adoption rule:** a change is adopted only if it improves the target metric on ≥ 3 of 5 folds AND does not raise
  false alarms per well-day. Otherwise log it as a negative result (keep it in the WORK_LOG).
- Every experiment gets a WORK_LOG row (E05, E06, …) plus a short notes section in the style of E02–E04.
- Run `pytest -q` at the end of every phase; all tests must pass.
- Every number in README / MODEL_CARD / LAUNCH_KIT / PRESENTATION_OUTLINE / facts sheet must come from
  `reports/final_results.json` (`tests/test_docs_numbers.py` enforces the headline KPIs).
- Hydrate-in-production-line results always carry the instrumentation-fingerprint caveat (T-MON-CKP exists only on
  hydrate wells' windows; see E03).
- Severe slugging: all 32 real instances come from 2 wells (31 from WELL-00014, fold 1), so it is effectively tested once.
- Words not to use anywhere: see the release brief (two banned terms for the author's role).

## Recommended feature set (E04)
`data/processed/features_physics.parquet` with the `PHY-` (ΔP levels) and `DRIFT0-` (start-of-file drift) groups
dropped = 6 stats × sensors + oscillation (`OSC-`, 2–60 min band, 120-min causal history) + live drift
(`DRIFTR-`, vs. mean over [t−3h, t−1h]) = 145 features. Defined in `configs/config.yaml` → `model.recommended`.
Rejected (negative results): ΔP levels (act as a well ID), start-of-file drift (instance-boundary artefact).

## Where results live
- `docs/WORK_LOG.md`: every experiment, with notes (E00 single-fold baseline, E01 superseded leakage check,
  E02 fair leakage gap, E03 sensor reliance, E04 physics features, E05+ release experiments)
- `reports/cv_results{_tag}.json`, `reports/cv_summary{_tag}.csv`, `reports/cv_events_grouped{_tag}.csv`
- `reports/cv_compare*.csv` + `reports/figures/cv_compare.png`: side-by-side runs
- `reports/final_results.{json,md}`: baseline (E02) vs final (E10), used by all docs

## Conventions
- Feature names: `<SENSOR or PSEUDO-SENSOR>__<stat>`; pseudo-sensor prefixes `PHY-`, `OSC-`, `DRIFT0-`, `DRIFTR-`.
  `--drop-sensors` takes exact sensors or prefixes ending in `-`.
- JSON reports are strict (NaN → null) via `wellsentinel.io.write_json`.
- Windows console is cp1252: scripts printing unicode call `sys.stdout.reconfigure(encoding="utf-8")`.
